# 行业多智能体协同

在「投资问答 → 行业分析」选择行业，在「多智能体协同」中展开「本次汇总的信息」，确认各模块资料后点击「开始多智能体协同分析」。结果、分项观点、实际执行状态、引用证据与待复核事项显示在下方对话，并沿用原有历史保存流程。协同独立使用深度研究，不改变普通咨询的模式。

本轮汇总当前登录会话里市场、个股、基金、可转债页面已加载的数据，以及各研究方向最近一次研究的结论摘要；结合当前行业的数据、资讯与已加载的行业走势。未加载模块会显示资料缺口，历史记录中尚未恢复到当前会话的研究不会自动全量读取。行业数据缓存只选当前行业，其他方向纳入同一后端的已加载缓存。

协同基于已有资料运行（auto_fetch=false）；需要补证时，先在相应模块加载或刷新数据，再重新发起协同。这样不会将行业名称错误地用作个股或转债的补查对象。

协调器并行调度市场、行业、证券、基金四个专业节点。证券节点同时处理个股与可转债，随后事实核验等待四个节点，风险检查再等待事实核验。普通行业咨询继续使用既有路由。

原始资料作为 FactRecord 送入现有时效、来源、冲突及引用核验。研究摘要和走势观察单独传入 reference_materials，不能直接当作事实或收益预测。其他证券或基金与行业的关联必须另有证据。无模型配置或模型输出无效时沿用规则降级，并保留资料缺口。

单次最多传入 4000 条事实；超过上限会在页面明确提示未纳入数量。相同编号对应不同内容的资料会被排除并提示。摘要每项最多 2000 字，截取时标注；不读取其他账号的状态，退出时清除会话资料与走势缓存。

## 查看投资逻辑的交叉验证与分歧处理

分析回答下直接显示交叉验证、风险检查和核验问题数量。展开「交叉验证与分歧处理」，可查看实际执行状态、同源与跨来源数据冲突、评分分歧或观点矛盾、各维度观点及引用、已剔除引用、相关原始记录对照和后续补证动作。处理原则与实际执行记录分开展示，保留的分歧不会被标为已解决。

系统保留分歧并要求复核，不按多数票形成投资结论。同一份数据被多个智能体引用、同源转载和派生评分均不算独立来源验证。人工复核意见在原有工作单记录，补证后重新分析才能更新系统审核结果。

新保存的历史记录保留分歧维度、问题级别和关联分析维度；历史问题明细仍限制为 20 项，并显示总数。早期记录未保存的名单、执行状态或原始数值显示为未记录，不由前端猜测补全。
