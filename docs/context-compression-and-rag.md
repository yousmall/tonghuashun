# 上下文压缩与 RAG 现状

## 自动上下文压缩

用户继续在同一个对话提问时，深度研究默认启用压缩。模型使用「最近原文＋更早的原文摘录」，对话片段的紧凑JSON预算为6000字符；这不是整个提示词上限，也不是6000个token。用户画像、授权事实、规则计算基线和当前问题另行输入，不在这项对话预算内。

短对话在预算内原样保留，当前问题从重复的对话末尾去重，完整当前问题始终保留在顶层`query`。长对话优先保留最近最多6条完整原文，给它们预留约4200字符，剩余预算选择较早的原文摘录。优先考虑明确限制、否定、标的、资金期限、回撤上限和用户更正，再考虑当前问题相关性与时间。摘录保留角色、来源轮次、时间和原文字符位置；长句片段另有`fragment`标记，不调用模型改写或总结，也不递归压缩旧摘要。超长数字片段的边界扩展到完整数字。

前端仍按API约定提交最多20条消息，不发送回答payload或完整证据。超过4000字符的消息使用带明确省略标记的头尾传输摘录，原始对话未修改。前端深度研究默认同时授权读取当前账号、当前对话、同一研究方向的历史，服务端最多读取200条、每条最多20000字符，仅查角色、文字和时间，不读取历史证据JSON。历史与客户端窗口按重叠消息合并，避免重复。历史读取超过2秒或不可用时，使用本次显式上下文，并记录降级状态。

压缩只面向模型调用，统一用于意图识别、专业研判和最终复核。3秒研究没有多轮模型，因此不为本功能读取额外历史或调用模型；固定推荐任务、行业协同任务也不会引入其他咨询历史。原始消息和证据仍保留，投资逻辑链的轮次查看与历史恢复不依赖压缩摘要。

API入参`context_compression`默认`true`；设为`false`时沿用最近10条原文，不读取额外压缩历史。`use_conversation_history`默认`false`，保持已有API客户端的显式上下文行为，第一方聊天前端自动启用。历史读取仍依赖有效登录租约和服务端账号归属，不接受客户端传入压缩记忆或其他用户ID作为可信来源。

返回的`context_compression`只包含策略、原始/压缩字符数、预算、最近消息数、摘录数、未进入的消息数、历史读取状态与模型调用次数；内部压缩内容是请求私有属性，不由API接受，也不写进返回包。统计随当前回答保存，入口为「投资逻辑链 → 选择咨询轮次 → 上下文压缩记录」。聊天气泡继续只显示分析结论、风险结论。

压缩是有损且有界的：并不保证所有旧约束都保留，特别长的单句可能只保留片段。超过历史读取上限或摘录预算时会记录省略；关键约束仍应在风险评估或当前问题明确确认。摘要只是未核实的历史语境，旧助手结论、数字和引用编号都不能代替当前授权事实；最新明确问题、更正和服务端已确认画像仍按既有规则处理。实际token用量与费用只来自模型供应商返回，不由字符节省比例推算。

## 项目是否使用 RAG

现已部署本地向量知识库RAG，使用FastEmbed的中文BGE-small-zh-v1.5 ONNX模型（512维、CPU），结合SQLite FTS5中文二元词项召回，以RRF合并排名。运行时只从本地加载模型，不向远程embedding服务发送资料。深入研究先获取当前供应商数据，再检索当前账号、相同标的与资产类型的资料和共享基础知识，将有效条目送入`authorized_facts`，继续经过原有事实核验、冲突检查、规则评分、数值对账和合规审核。

资料目录、部署和导入操作见[本地RAG部署说明](rag-deployment.md)。当前默认包含项目编写的12份投资基础知识及六类技术指标说明；这些是解释性材料，不是实时行情或官方研报。用户导入资料按账号隔离，取数流程自动保存最多40条本次新获取、有效且非派生的供应商原始事实。风险画像、持仓、交易记录、历史助手回答与压缩记忆不会自动进入知识库。

3秒研究、固定推荐任务和行业协同不增加向量检索。API可通过`use_rag=false`关闭本轮知识库补充；服务可通过`WENCE_RAG_ENABLED=false`关闭。检索失败有明确审计状态，研究继续执行原有取数与核验流程。检索事实保留原始时间、单位、来源和ID；行情仍按60秒时效校验。用户文档只是资料摘录，不自动转换成结构化价格或财务指标，不能填补规则计算必需的数值缺项。

RAG旨在降低无依据生成，不能保证消除幻觉；资料可能过期、错误、漏召回，模型也可能错误解读。相似度是相关性分数，不是准确率。实际幻觉率变化和真实模型效果需要独立业务问题集评估，部署与离线回归结果不代表该项评估已经完成。

## 实现与验证

- 压缩、传输摘录、窗口合并：`backend/app/services/context_compression.py`。
- 所属账号/对话/方向过滤的轻量历史读取：`Database.get_conversation_context`。
- 三处模型输入：`semantic.py`的意图与复核、`llm_agents.py`的专业研判。
- 当前检索及核验：`research.py`、`disclosure_reader.py`、`model_input.py`、`coordinator.py`、`numeric_grounding.py`。
- 离线回归：`tests/test_context_compression.py`，包括预算、原文位置、否定和更正、数值边界、历史隔离与降级、旧回答不可作为授权引用、前端请求与逻辑链审计。

测试使用合成历史、离线模型和本地SQLite，不证明真实模型幻觉率降低的幅度或实际token节省比例；真实端到端效果需用业务问题集和当前外部数据/模型另行评估。
