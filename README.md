# 问策智投

当前已实现可运行的投研辅助闭环：识别用户意图、生成并确认多维画像、生成可执行 Task DAG、并行调度宏观/行业/个股/基金/组合五类智能体、单一授权来源内的资料与跨智能体一致性检查、事实核验，并以合规审核作为最终闸门。

系统同时提供账号注册/登录和 MySQL 对话持久化。密码使用带随机盐的 scrypt 哈希保存，前端通过有过期时间的 Bearer 令牌访问当前用户自己的历史记录；不同用户不能读取彼此的会话。应用级线程池默认提供 100 个工作线程和 100 个登录会话槽，登录成功后分配会话槽，连续 10 分钟没有用户操作会回收槽位并要求重新登录。

系统支持两种运行模式：

- `rule_only`：未配置模型时的降级模式。问卷计分、事实核验和独立规则组件仍可用；自然语言分析返回澄清，画像文本保留待补充字段，不再用关键词或正则猜测。
- `hybrid_llm`：大模型负责意图与请求风险识别、画像文本提取、专业研判、输出合规及意见矛盾复核。代码保留问卷公式、数值上限、事实引用与时效校验；模型不能覆盖这些硬约束。

无论哪种模式，系统都不会自动下单，也不会把缺失数据补造成事实。

`POST /api/v1/portfolio/analyze` 默认使用 `research_mode="lite"`：仅整理已提供资料、执行固定风险检查或解释标准概念，不调用模型，也不自动取数；响应说明本次范围与省略功能。需要自然语言识别、最新数据及专业研判时，显式传 `"research_mode": "deep"`。历史保存方面，lite 响应中的 `history_status="pending"` 表示正在异步保存，调用方应在随后读取历史确认；deep 等待保存后返回 `stored`。

deep 模式默认开启自动取数闭环：意图识别后，大模型同时从 16 类问财只读能力白名单中选出本轮问题明确需要的数据；后端将它们与该意图的固定最小证据集合并，并行调用尚未查询或已经过期的能力。响应会标准化为事实，按公开规则生成带输入血缘的派生评分，再进入事实核验、专业智能体、交叉验证和合规闸门。模型不能提供方法名、URL 或任意参数，也不能绕开后端直接执行工具。响应中的 `data_acquisition` 明确区分 `live`、`mixed`、`reused`、`unavailable` 等状态，`facts` 返回本次完整证据包。调用方可显式传 `"auto_fetch": false` 关闭自动取数。

默认自动研究只调用问财 SkillHub 这一授权市场数据源。交叉核验检查事实引用、时效、派生血缘、问财内部同项记录和分项观点；单一来源通过核验不等于获得独立来源确认。最终响应的 risk_conclusion 由核验状态、已确认画像与固定风险规则生成：证据不足或数据冲突时给出待复核结论，触及持仓上限等规则时明确指出风险，不把规则通过写成“低风险”。历史记录保留同一字段。

首次分析发现关键维度缺失、引用失效或同项资料冲突时，系统最多追加一轮相关只读能力补取，绕过本地事实复用及进程缓存；各调用仍受原有超时限制。新增有效资料会重新进入完整的专业分析、事实核验、交叉验证及合规流程。`data_acquisition.recovery_*` 记录补取能力、成功/空结果/失败及是否重新分析。原始冲突记录保留，补取失败也不抹去风险；纯观点分歧、尚未由财报验证的提价影响、未提供的研究对象或个人偏好仍需保留不确定性。关闭 `auto_fetch`、画像/入口闸门未通过或合规拦截时，不触发补取。

## 网页研究模式

投资问答页面只提供「3秒研究」和「深度思考」两个模式。默认的「3秒研究」使用已加载且通过核验的资料，在 3 秒预算内给出证据概要；需要新资料时先刷新页面数据或改用「深度思考」。「深度思考」可以在线补查资料，完成专业分析、事实核验和审核，不设置整次研究的总时限；单次模型、数据源调用及连接建立仍有故障超时，外部服务故障可能使研究失败。

可在任一研究页输入「分析下茅台」，再问「和五粮液比较去年年报」。客观筛选示例为「筛选 ROE 超过 15% 的非 ST 股票」。按投资偏好推荐和完整深入报告仍有各自入口。追问里省略标的（例如先问「600519 的市盈率」，再问「它的市净率呢」）时，精简与即时研究按当前会话最近一轮提到的标的补齐，并在结论开头注明沿用的标的；换成市场、行业等其它范围的问题时不沿用上一轮标的。

## 走势、指数与行业分析

- 历史走势接口支持股票、可转债、基金、**指数和行业**；返回真实交易日期序列、**五日均线（MA5）序列**与一份确定性走势分析。
- **连续三日上升高度**：最近 3 个交易日的累计涨幅、绝对高度（与行情同一计价单位）、逐日涨跌幅与连续上涨天数；不足 4 个交易日不计算。
- **中和判断走势**：六个可复算信号（MA5 斜率、价格相对 MA5、MA5 相对 MA20、三日升幅、五日方向一致性、相对基准强弱）加权为 0–100 分与档位；多空信号同时成立时按“中和”规则降级为震荡，并输出每个信号的方向、得分、权重与解释。
- 市场页新增**主要指数看板**：上证指数、深证成指、创业板指、沪深300、中证500、科创50 的报价、MA5、三日升幅与判断，附起点归一为 100 的走势对比和单指数信号拆解；单个指数历史缺失只影响自己的卡片。
- 行业页在选定行业后可**按需加载行业指数走势**，口径与个股一致。
- 走势类数据只用于图表与描述性观察，**不进入投资建议的 facts、证据与合规链**；判断不预测收益。计算口径见 [走势与投资价值比较](docs/trend-and-decision.md)。

## 自选研究：名称补全与投资价值比较

- 添加自选时后端会做一次只读身份查询，把代码补全为数据源核实的证券简称并落库；名称展示顺序为“数据源核实名称 → 账号保存名称 → 用户输入”，对比表头、详情下拉与走势选择器统一显示“名称 · 代码”。
- 横向比较 2–4 个同类型标的后，返回 `decision`：按估值、成长、盈利质量、资金、当日表现五个维度，用“组内相对档位 50% + 绝对区间 50%”的固定规则排序，给出哪个相对更具投资价值、优势与不足、与第二名的分差。
- 缺失指标不按 0 分参与：同一维度要求所有标的同口径有效，否则整体退出并列入“未纳入比较的维度”；亏损公司的负 PE/PB 不当作便宜，改用市净率或退出估值维度。
- 估值/成长/盈利质量至少覆盖两项才输出排序，否则明确返回资料不足。结论标注“不是预期收益、不是上涨概率、不构成买入建议”。

## 结构化投资分析报告与可视化面板

- 分析响应中的 `research_report` 已扩展为结构化报告：结论、关键信息（有利/不利/中性）、数据覆盖（引用/可用/带日期条数、已覆盖与未覆盖维度、来源分布）、分维度证据与重新评估条件。
- 回答下方可下载 **Markdown 报告**（`POST /api/v1/research/report/markdown`），PDF 导出保留。
- 回答下方提供**「分析过程与结论可视化面板」**：分析过程页展示阶段耗时、取数与补证统计、任务节点与模型调用明细；结论页展示合规状态、置信度、规则分/模型分对比、资料来源分布与风险清单。面板只渲染响应中的审计字段，不前端推算。
- 答辩口径、字段对照与演示脚本见 [可视化面板答辩说明](docs/defense-visualization-panel.md)。

## 个性化投资建议与资产配置

咨询对话仅展示分析结论与风险结论；过程、图表、核验和报告统一放入当前对话共用的投资逻辑链，按咨询轮次查看。详见[对话与投资逻辑链](docs/conversation-logic.md)。

在“风险评估”中确认保存问卷后，进入侧栏“投资规划”，查看自动投资规划、个性化投资建议及资产配置。配置结合投资目标、用款期限、应急储备、负债和回撤约束，包括三类资产参考比例、建议依据、压力情景及复核安排。填写明确投资金额可换算资金安排，金额合计精确到分。收益目标不会放宽风险约束，未确认或过期测评不生成配置。详见[使用说明](docs/personalized-investment.md)。

侧栏账号卡下方的“个人设置”支持自定义昵称与头像；默认昵称为“用户”加8位数字字母混合字符，风险结果卡同步使用用户头像。详见[账号个人设置](docs/user-settings.md)。

## 启动 API

2026-11-16图片要求补齐与最新验证见[验收记录](docs/requirements-acceptance-2026-11-16.md)。深入研究不要求3秒，使用独立有界等待队列；精简咨询保留快速响应目标。支持用`.venv/Scripts/python.exe scripts/serve_resilient.py --port 8000 --workers 2`启动带有限故障重启的本机API。`GET /api/v1/readyz`实际探测数据库连接；30天观测仅在窗口完成并核对采样覆盖后评估，不由短时成功率替代。

使用 Python 3.11 或更高版本。

```powershell
python -m pip install -r requirements.txt
python -m uvicorn backend.app.main:app --reload --port 8000
```

启动后访问 `http://127.0.0.1:8000/api/v1/health`，预期返回 `{"status":"ok"}`。
接口文档位于 `http://127.0.0.1:8000/docs`。

就绪状态和运行指标：

- `GET /api/v1/readiness`：显示当前是规则模式还是混合大模型模式，以及问财数据源是否已配置。
- `GET /api/v1/metrics`：显示单进程请求量、失败数、观测成功率和 P50/P95/P99 延迟。该接口用于运行观测，不冒充生产 SLA。
- `GET /api/v1/metrics/prometheus`：把同一份进程内观测以 Prometheus 文本格式（`wence_*` 指标族）暴露，可直接被 Prometheus 抓取；登录失败限流的计数与剩余锁定也在其中。

登录接口对同一账号加来源 IP 的连续失败次数做限流：默认 10 分钟内失败 5 次后锁定 60 秒，锁定期间返回 `429` 并带 `Retry-After`；可用 `WENCE_LOGIN_MAX_FAILURES`、`WENCE_LOGIN_WINDOW_SECONDS`、`WENCE_LOGIN_LOCKOUT_SECONDS` 调整。

除组合诊断外，画像和规划接口包括：

- `POST /api/v1/profile/assess`：问卷/文本生成**未确认**画像草稿，并返回提取证据和缺失字段。
- `POST /api/v1/profile/confirm`：显式确认画像并递增版本号；已登录账号使用版本校验避免旧标签页覆盖新画像。已登录分析只使用该账号服务端保存的已确认画像；请求版本过期时返回 409。
- `POST /api/v1/profile/investment-plan`：从当前登录账号已确认的问卷只读生成个性化建议与资产配置；可提交 `investment_amount` 换算参考金额，不接受客户端画像或风险等级。
- `POST /api/v1/portfolio/analyze/stream`：以 NDJSON 逐阶段返回取数、研判、事实核验和风险检查状态，最后才返回完整建议包。原同步分析接口仍可用。

组合与数值核验接口：

- `POST /api/v1/portfolio/plan`：确定性组合诊断。按单票/行业上限做约束投影，同时给出等权、逆波动、风险平价三种候选权重，并返回相关性矩阵、行业暴露、风险贡献、再平衡清单与换手率。全部为纯算术，不调用大模型，结果可复现。上限本身不可行时（例如 3 条持仓配 20% 单票上限）会放宽到最小可行值并在 `constraint_violations.relaxed` 与 `warnings` 里披露，不会静默超限或留下空仓。
- `POST /api/v1/research/grounding-check`：把一段投顾文字与一组事实做数值对账，列出缺少出处的数字。它同时被深度分析自动调用，结果写在建议包的 `numeric_grounding` 字段。

深度分析（`research_mode="deep"`）在请求已带 `research_direction` 与 `research_target` 时，会先把取数和意图识别并行跑起来：识别结果与方向一致就复用预取资料，不一致则丢弃重取。可用 `WENCE_SPECULATIVE_PREFETCH=off` 关闭。

用户、自选与历史接口：

- `POST /api/v1/auth/register`：注册账号并返回登录令牌。
- `POST /api/v1/auth/login`：登录并返回登录令牌。
- `POST /api/v1/auth/wechat/start`：创建微信扫码授权请求。
- `GET /api/v1/auth/wechat/callback`：微信开放平台授权回调；回调完成后登录页自动领取原有会话令牌。
- `POST /api/v1/auth/wechat/poll`：原浏览器使用一次性轮询凭据领取登录结果。
- `GET /api/v1/auth/me`：读取当前登录用户。
- `GET /api/v1/auth/session/status`：只检查租约状态，不刷新空闲计时。
- `POST /api/v1/auth/logout`：退出登录并立即释放会话槽。
- `POST /api/v1/auth/logout/beacon`：供本机 Streamlit 连接观察器在页面关闭后释放会话槽，只接受不能访问用户数据的随机回收凭据。
- `GET /api/v1/watchlist`：读取当前用户的自选研究列表；返回数据源核实的证券简称 `name`。
- `POST /api/v1/watchlist`：添加股票、基金、行业或可转债到自选研究，单个账号最多 50 项；添加时尽力把代码补全为核实名称。
- `DELETE /api/v1/watchlist/{item_id}`：删除当前用户的一项自选；不能访问其他用户的数据。
- `POST /api/v1/data/price-history`：已登录用户按需获取股票/可转债/指数/行业收盘价、基金单位净值的近 30/60 期带日期序列，并返回 `ma5` 序列与 `analysis`（MA5、三日升幅、中和判断）；只供走势图展示，不进入投资建议的证据与合规链。
- `POST /api/v1/market/index-board`：六大主要指数的报价、MA5、三日升幅与中和判断；服务端 60 秒有界缓存。
- `POST /api/v1/research/report/markdown`：把结构化投资分析报告渲染为 Markdown，供下载留档。
- `GET /api/v1/history`：按账号读取会话列表，支持 `limit`、`offset` 和标题搜索 `q`。
- `GET /api/v1/history/{conversation_id}`：默认读取最近 40 条消息，支持 `before_id` 和 `limit` 继续加载更早消息；返回 `next_before_id`。
- `PATCH /api/v1/history/{conversation_id}`：重命名当前用户的会话。

## 管理员后台

管理员使用同一登录页，登录后只显示「注册用户」「咨询统计」「问财调用」。普通注册不能选择或获取管理员权限；管理 API 根据数据库权限校验，普通账号返回 403，未登录返回 401。

微信扫码登录需先在[微信开放平台](https://open.weixin.qq.com/)申请并审核「网站应用」及微信登录能力，在 `.env` 中设置 `WENCE_WECHAT_APP_ID`、`WENCE_WECHAT_APP_SECRET` 和 `WENCE_WECHAT_CALLBACK_URL`。回调地址须为公开可访问的 HTTPS 地址 `https://你的域名/api/v1/auth/wechat/callback`，并使用开放平台登记的授权回调域名。二维码与扫码状态保存在单个后端进程内，部署时须使用一个 Uvicorn worker；状态 5 分钟过期。微信账号首次扫码创建独立普通账号，后续扫码恢复该账号的历史记录，管理员身份不会经微信扫码授予。

配置好 MySQL 后，用项目 Python 创建一个新的管理员账号：

```powershell
.\.venv\Scripts\python.exe scripts/create_admin.py --username admin
```

脚本生成随机密码并保存到本机 `.env.admin`（已被 `.env.*` 忽略规则保护），数据库只保存密码哈希。脚本不会提升或重置同名的已有账号，也不会覆盖已有凭据文件。后端启动时自动创建 `admin_roles`、`consultation_stats`、`iwencai_calls`，无需修改旧用户表。

- 注册用户：分页查看全部账号、在线状态、有效会话数、咨询次数和最近咨询时间，在线账号跨页优先；可搜索并查看某个用户的各领域咨询量及最近 50 个问题。一个账号多处登录只算一个在线用户，退出或空闲超时后转为离线。在线状态来自当前后端进程的有效会话租约。
- 咨询统计：按每轮已保存的用户问题计一次，回看历史不增加次数；按股票、基金、行业、可转债、宏观与市场、组合配置、投资知识及其他领域，展示最多 5 个标的或主题。有研究对象时按对象统计，没有对象时按原提问主题统计。同名重复咨询合并，名称与证券代码不会自动合并为同一个对象。历史缺少领域信息的记录会幂等补齐到「其他 / 未分类」，不会猜测分类。
- 问财调用：持久记录每次实际 HTTP 尝试的接口、状态码、成功/失败、空结果、资料条数与耗时。重试逐次计数；缓存复用、未配置数据源和熔断前拦截不算实际调用。日志不保存密钥、请求正文或上游响应内容；写入失败会在管理页提示统计可能不完整。日志从启用功能后开始累计，无法还原此前未记录的请求。

支持全部时间、最近 7/30/90 天筛选；点击刷新更新。明细时间显示北京时间，按天趋势使用 UTC 日期。

管理接口：`GET /api/v1/admin/users`、`GET /api/v1/admin/statistics`、`GET /api/v1/admin/users/{username}/consultations`、`GET /api/v1/admin/iwencai`，均需要管理员 Bearer 令牌。`days=0` 表示全部时间；用户列表支持 `q`、`offset` 和 `limit`。

## 配置 MySQL

线程池采用“逻辑会话槽 + 按需工作线程”的方式：空闲用户不会永久占用 OS 线程；数据库持久化等阻塞任务在已认证请求期间提交到固定线程池。执行中的请求不会被空闲清理器回收。`GET /api/v1/readiness` 和 `GET /api/v1/metrics` 的 `session_thread_pool` 字段会返回最大工作线程、活动会话、在途请求和剩余槽位。

Streamlit 每次由用户操作触发完整重跑时都会刷新活动时间，并以不刷新活动时间的状态轮询发现已过期租约。页面关闭后，Streamlit 服务器通过活动连接状态在约 3 秒宽限期后调用回收接口；为防止回收凭据被发送到外部地址，即时关页回收只对本机回环 API 启用，其他部署仍由 10 分钟服务端超时回收。

`.env` 已被 Git 忽略，禁止把真实数据库密码或签名密钥写入 `.env.example` 或提交到仓库。

`POST /api/v1/portfolio/analyze` 的 `facts` 中每项必须包含带时区的 `snapshot_time`（如 `2026-08-29T08:00:00Z`）、`source_id` 与 `quality`。超过核验时效、来源为空或质量过低的事实会被自动移出最终证据并触发 `REVIEW`。

时效按数据类型区分：实时行情 60 秒、新闻/公告/研报 5 分钟、标准化投研评分 15 分钟、持仓快照 1 天、慢速财务指标 90 天。同一授权来源内，同一报告期或相同时点的同项数据冲突，以及多个专业智能体评分显著分散，都会进入 `cross_validation` 并触发人工复核。核验通过表示现有资料内部未发现这些问题，不代表经过独立数据源证实。

同名字段会按口径拆分，不做子串合并：问财一行同时返回市盈率 TTM、静态市盈率和动态市盈率时，分别标准化为 `pe_ttm`、`pe_static`、`pe_dynamic`；普通与加权净资产收益率分别为 `roe`、`roe_weighted`；涨跌幅（%）与涨跌额（元）分别为 `change`、`change_amount`。新闻、公告、研报、事件天然同源多条，因此不参与“同一项记录取值是否自相矛盾”的比对，只作为并列证据逐条引用；机构调研按“每家机构一行”返回，同样按行比对。单条记录的身份由链接、标题或正文决定，不使用发布日期，因此同一实体的多条记录不会互相判为冲突（多机构评级、研究员、研报链接等行级字段也因此不会被误报）。

## 接入第三方大模型

任何提供 OpenAI-compatible Chat Completions 接口的第三方模型均可接入：

```powershell
$env:DEEPSEEK_BASE_URL="https://你的模型服务/v1"
$env:DEEPSEEK_API_KEY="你的模型密钥"
$env:DEEPSEEK_MODEL="模型名称"
```

模型对话输入默认采用6000字符JSON预算的自动压缩：保留最近原文，按相关性、用户约束及更正摘录更早原文；画像、授权事实和规则基线继续单独完整核验。前端深度研究可按当前账号、对话及方向读取最多200条历史消息；API显式上下文仍最多20条。详见[上下文压缩与RAG现状](docs/context-compression-and-rag.md)。意图、画像和复核使用受限 Schema；专业输出通过 `AgentResult` 校验，引用来源由事实层重新生成。专业节点先由规则引擎算出确定性评分，再交给模型解释；模型返回空评分时沿用规则基线分数，不能把节点从共识与评分分散核验中静默摘除。画像只提取有原文证据的允许字段，永远先生成未确认草稿；结构化填写优先于模型提取。

调用量按固定流程控制：

- 一次分析只做一次意图、请求风险和所需问财数据能力判断，取数和编排直接复用结果；风险请求在取数和专业节点前返回。
- 专业节点按意图选取，最多 5 个；所有意见的语义合规和矛盾检查合并为一次调用。正常完整分析最多 7 次逻辑调用，画像评估有文本时最多 1 次。
- 同一进程的语义服务与专业智能体共享客户端，默认最多 5 个模型请求并发；每次逻辑调用默认 30 秒总预算，包含排队、网络和重试；专业节点与合规节点的等待上限随模型预算同步调整。
- 意图识别与合规复核的 `reason` 在成功和失败判断中都必须非空，纯空白也不合法。仅当其他字段全部合法且理由为空、缺失或 null 时，最多增加一次只补理由的模型调用；不能改动意图、置信度、风险规则、冲突节点或取数能力。初次调用和补正共享原有模型超时预算；补正仍无效则安全降级。原始失败与补正结果分别计入 `model_calls`，不缓存空理由响应。正常调用数量不变，发生此类异常时每个语义节点至多额外一次补正。
- 仅网络故障、429 或 5xx 最多重试 1 次，因此完整分析的 HTTP 尝试数上限为 14；认证失败和无效 JSON 不重试。可设置 `WENCE_LLM_MAX_RETRIES=0` 进一步节省调用。
- 每次默认输出上限 2000 tokens，输入上限 60000 字符；超限直接降级，不截断证据或用户语义。不使用跨用户文本缓存。
- 按问题补充取数：固定意图路由负责基础证据；当用户进一步询问公告、主营构成、股东结构、研报等数据时，模型只能追加对应的白名单能力，后端负责实际调用并把结果转成 `FactRecord`。非法能力名会被结构化校验拒绝。
- 追问不重复取数：同一研究对象的资料若**整批仍在各自时效内**，直接沿用而不再次调用外部数据源，审计结果记录在 `data_acquisition.reused_capabilities`。研究对象由语义判断一并抽取，只用作"这份资料是否已经取过"的复用键，不改变发给数据源的查询文本；组合诊断以持仓集合为研究对象。抽不到研究对象时退回按原话匹配——换一种问法就会重新取数，这是刻意的保守行为。该机制同时适用于模型追加的能力，只省去取数那一段，模型生成时间不变。

取数复用的判据刻意不维护"哪些字段才算够用"的清单：数据源每次返回的字段并不稳定，按字段清单判断会让一次缺字段就永久无法复用，而且映射一旦与实际返回不符，就会出现"少取了资料却没人发现"的隐性损失。只带查询摘要（`provider_response`）、没有任何业务字段的调用不算"已经取到资料"，下一轮必须重试。

可通过 `WENCE_LLM_TIMEOUT_SECONDS`（大于 0、最多 60）、`WENCE_LLM_MAX_RETRIES`（0 或 1）、`WENCE_LLM_MAX_CONCURRENCY`、`WENCE_LLM_MAX_OUTPUT_TOKENS` 和 `WENCE_LLM_MAX_INPUT_CHARS` 调整限制，默认值见 `.env.example`。

`WENCE_LLM_THINKING_MODE=auto` 默认对 DeepSeek V4 设置 `thinking.type=disabled`，避免思考 token 耗尽 2000 token 预算后正文为空；其他模型不发送这个扩展参数。也可显式选择 `disabled`、`enabled` 或 `omit`（由服务商决定）。启用思考时需为思考与正文共同预留输出预算；客户端拒绝 `finish_reason=length` 的截断结果。参数协议见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

模型未配置、超时或输出非法时：意图返回 `unknown`，理由为统一的重试提示；模型给出判定但置信度低于 0.65 时：意图同样保守降级为 `unknown` 并澄清，但沿用模型写明的具体理由（例如"未指明研究对象"），让用户知道该补充什么，而不是收到与真实原因无关的"语义判断不可用"；画像不推测缺失值；专业输出保留规则基线；最终语义审核失败进入 `REVIEW`。就绪接口的 `language_processing` 表示自然语言能力是否已配置。

直接使用 Python 接口时，`assess_profile` 和 `understand_intent` 现在需要 `await`；同步 `plan` 需要传入已判断的 `Intent`。建议优先使用异步 `CoordinatorAgent.run`，或用 `understand_request` 取得结果后通过 `understanding=` 传给 `run`。

## 启动 Streamlit 前端

先在一个终端启动 API，再打开第二个终端并执行：

```powershell
python -m streamlit run frontend/streamlit_app.py
```

浏览器访问终端显示的地址（通常是 `http://localhost:8501`）。首次进入先注册或登录，在“投资偏好”中填写并确认个人情况，即可开始研究。

投资问答中的每条回答会展示资料与风险图示；已引用的同日期数值资料足够时，还会展示走势或指标对比图。回答下方的“导出这条回答为 PDF”可下载包含问题、正文、图片、风险提示和来源的中文报告。自选横向比较支持 2–4 个同类型标的，混合类型会提示分别比较。非 Windows 部署如没有中文字体，可通过 `WENCE_REPORT_FONT` 指定可用的中文 TrueType 字体路径。


前端提供四个投资入口：投资问答、自选研究、持仓分析、投资偏好。侧栏另有“新建对话”和可收起的“最近聊天”；历史详情可从“查看全部聊天”进入，支持搜索、重命名和按需加载更早消息。研究工作台在已有对话时默认收起。分析中显示后端真实阶段，核验完成前不展示结论。

- 投资问答：可以按研究方向（个股、行业、市场、基金、可转债）提问，也可以直接对话；结果中的引用资料展示来源、时间及经校验的原文链接（有地址时）。
- 自选研究：按账号保存股票、基金、行业和可转债自选项，支持一键发起研究，并可选择 2 至 4 项进行横向比较；股票/基金/可转债可按需加载问财历史收盘价或单位净值折线图，日期不足或数据源不可用时不绘制曲线；内部记录编号不在业务界面展示。
- 持仓分析：除组合诊断外，增加由用户录入权重生成的持仓环形图、仓位分布、最大/前两大持仓、单一标的上限、未配置仓位和机械压力测试。占比超过 100% 时暂停绘制环形图；压力测试只做确定性情景测算，不作为价格预测。
- 历史详情：包含“对话记录”和“分析详情”两个页签，按分析记录查看分项观点、实际引用与未引用资料、完成情况；内部评分、节点编号等不展示。

结果仍以结论、注意事项和下一步为主，详细信息按需展开。新对话会保留事先准备的研究资料；清理当前资料不会改动已有分析的依据。历史对话可恢复后继续提问。

界面采用"品牌酒红 + 中性冷灰"的终端式视觉：品牌主色保持 `#AD384E`，正文与数据回到高对比底色，侧栏为整行高亮的胶囊导航，页面顶部条显示资料条数与偏好确认状态，首页与持仓页以数据卡概览关键数值，风险/合规提示用红、正常/已完成用绿。样式分层如下：

- 颜色、字体、圆角、语义色与图表色板：`.streamlit/config.toml`
- 页面底色层次、卡片、侧栏导航、数据卡与空状态：`frontend/assets/app.css`
- 页面结构、数据卡内容与状态徽标：`frontend/streamlit_app.py`

页面底色使用品牌玫红竖向渐变（顶部约一半为纯色平台，下半段过渡到 `#FEFEFE`），以 CSS 渐变等价实现，因此不再需要随项目保存背景图片；卡片、指标卡与空状态统一改为实心白底并加一层淡阴影，保证在粉底上仍有足够对比度。页面不展示启动命令、演示数据入口、服务状态或智能体内部指标；开发与诊断说明保留在本文档和 API 中。

### 研究界面与行情缓存

- 首次使用保留完整操作引导；投资偏好确认后，首页提供继续研究、自选、持仓风险入口与市场概览，使用说明可展开。
- 登录启动五个方向的预取。研究数据在后台加载，行情、财务、资讯分别更新，底部输入不等待概览；加载完成后停止快速轮询。概览仅用于浏览，不自动进入投资分析证据。
- 账号的投资偏好、最近咨询与自选列表并行预取，首屏不等待资料读取；资料完成后自动更新。偏好恢复前不开放修改，自选列表恢复前不开放添加，避免旧读取覆盖新操作；退出登录清理任务与结果。
- 图表依赖按页面需求导入；登录成功后复用已验证的会话状态，并每 30 秒复验租约。读取失败短暂缓存 30 秒，避免控件重跑重复等待。
- 后端启动先完成表结构准备，历史咨询统计分批在后台补齐；补齐期间管理员的历史聚合统计可能尚未完整，新增咨询仍实时记录。
- `/api/v1/data/overview`、`/data/compare`、`/data/watchlist-quotes` 均要求客户登录。自选行情仅读取当前账户最近加入的 20 项；横向对比限定 2–4 个同类型标的，服务端逐项核对证券身份。
- 公共供应商事实使用进程内缓存与同一请求合并：最多 64 个键、32 个待完成任务、8 个并行任务；行情缓存 60 秒，基金/新闻/历史 300 秒，财务/公司资料 900 秒，宏观 1800 秒，失败 30 秒。取数包括排队最长 28 秒，强制刷新每键间隔至少 10 秒。多进程部署时各进程独立缓存。
- 对比矩阵优先采用共有的最新期间，并显示单位、日期、缺失与冲突。季度数据保持财报期间，不混同交易日；日期或单位不齐时不强行排序，也不把缺失值补成零。
- 网页使用响应式卡片与交互图表，历史回答折叠分析细节但保留风险；PDF 保留完整正文、来源和高清图示。历史存储格式 v2 保留分项引用、证券代码、原始指标字段和派生关系，仍限制最多 60 条事实；旧记录缺少的引用不虚构恢复。
- 前端展示、回答报告、首页、自选、HTTP 传输和后台快照分别放在 `frontend/presentation.py`、`result_views.py`、`home_page.py`、`watchlist_page.py`、`api_client.py`、`snapshots.py`，入口保留页面编排与业务回调。


### 行业查询与人工复核

- 行业分析页顶部的「查询行业」支持选择常用行业或输入新行业名称 / 板块代码，回车后重新查询该行业行情和资讯；修改选择即可换行业，「全部行业概览」恢复排名列表。「刷新数据」更新当前行业。行业选择只影响数据浏览区，发起咨询时请在问题中写明行业。
- 研究结论下展开「交叉检验与人工复核工作单」，先查看本次待核实事项和相关事实，再核对原文、行业分类、统计期、单位及派生依据。单一来源、同源转载或多智能体引用相同材料不构成独立来源验证。缺失值不能按零处理，亏损行业的负市盈率不能解释为低估。
- 填写复核人、原文依据与逐项说明，选择「仍待补证」「存在异议」或「人工核对无异议」，保存后可下载 JSON 记录。「无异议」要求完成全部检查并提供原文依据和可核对资料。意见只保留在当前登录会话，退出后清除，请下载留存；结果或证据变化后需重新复核。
- 人工记录独立于系统审核，不覆盖 REVIEW/BLOCK、不解除风险拦截。补齐缺项后刷新资料，重新提交分析，由系统再次核验。该入口不提供资料上传或服务端审批功能。
